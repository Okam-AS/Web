CAUSE, confirmed from the EF command log in the same run — BuildDetailAsync issues both approval
queries against the CURRENT version's id:

  SELECT ... FROM "GrowthNewsletterApprovals" WHERE "NewsletterVersionId" = @__version_Id_0
    AND "InvalidatedAt" IS NULL LIMIT 1                      -- the live lookup
  SELECT ... FROM "GrowthNewsletterApprovals" WHERE "NewsletterVersionId" = @__version_Id_0
    ORDER BY "Id" DESC LIMIT 1                               -- the "last invalidated" lookup

An edit APPENDS the version this second query then looks in, and invalidates approvals that bind the
version it left behind — so the second query can never return a row. `invalidatedAt` was dead on the
wire, not merely wrong after an edit.
