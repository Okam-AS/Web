# Brief — L-JOURNEY-PORT-HARDCODED

## Objective
a journey spec stops being green only on the default port

**Found the only way it could be found — by running on a non-default port.** `L-JOURNEY-MEALS` did, and
`test/e2e/journeys/meals-statement-month.spec.js:72` **hard-codes 4010** and ignores `E2E_FIXTURE_PORT`.
**Four sibling specs read the variable correctly**, so this is one file out of step rather than a
convention nobody adopted.

**Why it is worth a lane rather than a note.** A spec that is green only on the default port is green only
when nothing else is running — and this program routinely walks several journeys at once, which is exactly
when a second fixture needs a second port. The failure it produces is not a clear refusal; the walk talks
to **somebody else's fixture** and reports on a world it did not build.

The finding lane hit precisely that: its non-default run reddened the spec and **displaced a sibling's
canonical artifact**. It kept the superseded copy and restored green on 3010/4010 rather than leaving the
damage, which is why this is a small lane and not a recovery.

**Prove it on a non-default port**, not by reading the diff. A test that reads `E2E_FIXTURE_PORT` and is
only ever run on 4010 is indistinguishable from one that ignores it.

## Exit criteria
meals-statement-month runs green on a non-default fixture port as four sibling specs already do, shown by a run on a non-default port recorded in lanes/L-JOURNEY-PORT-HARDCODED/evidence.md
