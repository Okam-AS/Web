## Objective
a foreign social-security number is refused or recorded as accepted

**The guard refuses a fødselsnummer specifically rather than national identifiers generally.** It rejects
eleven digits passing both mod-11 control weightings — which is precisely the shape of a Norwegian personal
number and nothing else. **A German social-security number is twelve characters and contains a letter**, so it
fails that test, **passes the guard, and lands on statement lines the service's own comment says are frozen.**

**The finding is worse than the label that produced it.** A translation lane was checking whether a string
should exist before rewording it, found the surface *forbids* a personal number rather than displaying one —
so no privacy leak in the label — and then found this underneath.

**Decide and state which exit you are meeting.** Refusing the broader shape is one answer; recording the
acceptance as deliberate, with what makes it safe on a frozen line, is the other. **Do not widen the guard by
guessing at a pattern** — a rule that refuses "things that look like identifiers" will refuse legitimate
references and be switched off.

**C1 is why the frozen line matters**: a value that should never have been recorded has no later repair, and
the comment saying the line is frozen is the point rather than colour.

**The SQL trap is live — three lanes hit it today.** Put `Database!=SqlServer` in the filter explicitly; a
SQL-tier red is one you have no grant to interpret. **Read at the tip with `git show 8e2b57de:<path>` and name
the ref** — the checkout sits on a lane branch and the world doctor reports it as a mismatch.

## Exit criteria
