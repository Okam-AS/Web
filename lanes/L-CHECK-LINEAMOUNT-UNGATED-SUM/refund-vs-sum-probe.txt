PART 3 — the refund the operator hands back.

world      till took    OLD refund                        NEW refund
present    kr 50,00     kr 50,00                          kr 50,00
zero       kr 0,00      kr 0,00                           kr 0,00
absent     kr 50,00     kr 0,00                           refused: the amount is missing
partial    kr 50,00     kr 20,00                          refused: the amount is missing

THE ASSERTION THIS LANE TURNS ON:
  OLD   absent = kr 0,00    zero = kr 0,00   <-- THE SAME. The absence is invisible in the money.
  NEW   absent = refused: the amount is missing    zero = kr 0,00   <-- THEY DIFFER. The absence is refused instead of refunded.

  A test asserting only the SUM would pass on a fix that still built the wrong return;
  a test asserting only that a refund EXISTS would pass on the old code. The falsifying
  assertion is that these two worlds stop agreeing about money.


PART 4 — the deposit tag, and why it could not stay on `> 0`.

world      OLD sum  tag(`>0`)   NEW sum  tag(`>0`)          tag(isAmountInPlay)
present    1000     true        1000     true                true
zero       0        false       0        false               false
absent     0        false       null     false               true
partial    500      true        null     false  <-- SILENTLY OFF true

`present` and `partial` both show the tag today. On `> 0` alone, `partial` loses it the
moment the sum is gated -- a row that HAS pant quietly stops saying so. `isAmountInPlay`
keeps the stated zero silent and gives the unstated row its tag, carrying the unknown mark.
