WHY THE VALUES CANNOT BE GUESSED IN THE FIRST PLACE
  * `MealsStatementLine` carries NO membershipId and NO applicationUserId, on the entity or the DTO.
    The membership id reaches the wire only AS THE VALUE of memberDisplayRef, in the no-reference
    case. There is no second field to join against.
  * The two rendered values are drawn from different alphabets and match nothing else on the payload:
      ANS-2287                                    a company payroll code
      4b050000-0000-0000-0000-000000000002        a bare membership id
      stl-… / alc-… / ord-… / K-2026-…            every other identifier on the same rows
    A page printing a constant fails one; a page printing a prefix-plus-an-id fails both.
  * Asserted with toContain/toEqual BY VALUE, never on non-emptiness.
