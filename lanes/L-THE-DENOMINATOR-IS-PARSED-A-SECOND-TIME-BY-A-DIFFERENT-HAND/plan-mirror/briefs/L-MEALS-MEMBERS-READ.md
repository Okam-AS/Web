# Brief — L-MEALS-MEMBERS-READ

export PLAN_ACTOR=agent:L-MEALS-MEMBERS-READ

## Objective
the enrolled set can be read back, not only written

**Two backend gaps `L-MEALS-ENROL-UI` hit while wiring the surface. It could not close either, said so,
and built the UI to state the gap rather than paper over it — which is why they are legible at all.**

**1. Nothing reads the enrolled set back.** A programme carries a **count**; only the write's own response
names identities. So the admin panel cannot pre-tick who is already enrolled, and the lane deliberately
left it unticked with the reason on screen: **a guess would silently un-enrol whoever it guessed wrong
about.** That is the correct call and it is not a fix — `GET /programs/{id}/members` is.

**2. A claimed-but-unenrolled member reads `eligible:false` with no reason code at all.**
`MealsQuoteService.cs:426` sets one only for *revoked* or *enrolled-outside-window*. **This is the dead end
the employee was actually sitting in** — the surface can tell them they are not eligible and cannot tell
them why, or what would change it.

Both halves are the same defect wearing different clothes: **a read that answers with less than the caller
needs to act.** A count without identities, and a refusal without a cause.

The reason-code half touches the quote path — **Meals is a money path**, so if the change reaches a write
rather than a read, C4 applies and the actor is named and asserted by value.

## Exit criteria
a programme's enrolled members are readable by identity so the admin surface can pre-tick them, and a claimed-but-unenrolled member's ineligibility carries a reason code, pinned by a test per half that reds if either returns to silence, recorded in lanes/L-MEALS-MEMBERS-READ/mutation-log.md
