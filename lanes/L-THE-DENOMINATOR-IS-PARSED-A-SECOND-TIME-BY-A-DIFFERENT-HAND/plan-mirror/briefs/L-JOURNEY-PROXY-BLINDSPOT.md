# Brief — L-JOURNEY-PROXY-BLINDSPOT

export PLAN_ACTOR=agent:L-JOURNEY-PROXY-BLINDSPOT

## Objective
a subject fetched through the same-origin proxy stops reading as zero

**Found by the Fable review of `L-LIVE-ASSERTION-FLOORS`, which approved the new guards and then named
the one shape they cannot see.**

`nuxt.config.js:138` mounts `server-middleware/okam-api-proxy.js`. A client built with
`API_BASE_URL=/okam-api` fetches its subject **same-origin** — and the recorder excludes same-origin
traffic (`origin !== this._appOrigin`). So a run that signs in at the named backend and then fetches its
whole subject through the proxy files `backendSubjectServed: 0, foreignSubjectServed: 0`: the judge stays
silent, every floor is green, and the artifact names a backend that answered **only the door**.

That is the same defect class the lane was built to kill, one layer down — a guard that cannot fail
because the world it measures never reaches it.

The reviewer named the change: count subject-shaped `xhr`/`fetch` whose origin is `_appOrigin` and whose
path begins `/okam-api/` into their own counter, file it in the artifact, red when
`subjectFromBackend == 0` while that counter is positive, and add a guard-proof arm for it. **Scope to
the `/okam-api/` prefix** so Nuxt dev-server fetches do not false-red.

## Exit criteria
a journey whose client fetches its subject through the same-origin /okam-api proxy is judged rather than counted as zero, pinned by a new guard-proof arm that reds when the branch is disabled, recorded in lanes/L-JOURNEY-PROXY-BLINDSPOT/guard-proof.txt
